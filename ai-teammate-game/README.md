# LAST OXYGEN · 最后的氧气

基于 pi Agent 的个人救援游戏原型。你受伤无法移动，氧气正在流失；机器人 R-07 精确看见近处的对象，而你通过雷达看到更远的模糊回波。通过对话、共享标记和资源取舍指挥机器人，修复气闸并搬运撤离。

## 启动

在 PowerShell 中运行：

```powershell
cd D:\pi\ai-teammate-game
npm ci
npm run dev
```

打开 **http://127.0.0.1:4317**。首次启动使用本地规则演示，**不请求模型、没有模型费用**，但仍通过真正的 pi Agent 执行工具和生命周期钩子。配置模型后，新的一局自动沿用已保存的默认设置。页面会明确标注当前模式。

需要 Node.js **24.4 或更新版本**。本工作区复用相邻 `../pi-main` 中已有的 TypeScript、esbuild、pi-agent 与 pi-ai 构建产物；本项目的 Three.js 依赖通过 `npm ci` 安装。运行前应存在：

- `pi-main/node_modules/typescript/bin/tsc`
- `pi-main/node_modules/esbuild/lib/main.js`
- `pi-main/packages/agent/dist/index.js`
- `pi-main/packages/ai/dist/index.js`
- `pi-main/packages/ai/dist/providers/all.js`（复用 pi 服务商与模型目录）
- `pi-main/packages/coding-agent/dist/config.js`、`dist/core/auth-storage.js`、`dist/core/runtime-credentials.js` 与 `dist/core/resolve-config-value.js`（复用 pi 用户目录、凭据存储与运行时覆盖）

当前采用 TypeScript、原生 DOM、Three.js 与 Node HTTP，不修改 pi 仓库源码。首次启动先执行 `npm ci` 安装本项目的 Three.js 及类型依赖；随后执行 `npm run dev` 即可。启动时重新打包网页；修改代码后重新启动生效。`npm run build` 可单独构建前端。另一个端口可通过 `$env:PORT = '4318'` 设置。

## 操作

界面参考 `../UI.png` 的圆盘式终端构图：大幅中央视窗、厚重分段环带、倾斜金属图标入口、底部黄色弧形操作带与左下身份卡。氧气、电量与游戏时间位于圆盘上沿。中央空间站采用 Three.js 正交相机和真实立体模型，以低分辨率渲染形成像素风；远处未知对象仍显示模糊回波。历史地图、近距感知、已确认对象与共享标记使用现有玩家知识，不读取隐藏实体。

3D 场景沿用界面的橄榄绿、灰白金属和荧光黄：铆钉地板、通风墙板、分层底座及边缘护栏构成工业舱室；R-07 配备履带、护甲和状态灯，伤员使用担架模型。氧气瓶、电池、维修箱、门柜及控制器有独立造型和可见状态。近距感知使用地板亮度与边界线，未知回波保留问号；同类零件批量渲染，纹理在本地生成。

地图支持鼠标左键拖动旋转、右键拖动平移、滚轮缩放；触屏使用单指拖动旋转、双指缩放和平移。拖动不会误选格子，点击或轻触仍选择原始地图坐标。黄色弧形操作带提供手动控制、复位与旋转 90 度，圆盘右下提供缩放按钮；WASD / 方向键沿地图坐标移动。调整窗口大小保留当前视角。

两侧入口打开附近操作、物资管理、生命监测、救援目标、共享标记、行动记录、机器人通信和操作指南。点击地图后，可通过圆盘下部的坐标提示打开位置详情。桌面使用侧边面板，手机使用底部面板；关闭按钮、Escape 或点击面板外部可返回地图，关闭后焦点回到入口。窄屏将图标入口排列在圆盘下方，允许纵向滚动；长对话与行动记录在面板内部滚动。任务进度、资源预警、授权、存档和回放仍与游戏状态同步。设备无法创建 WebGL 2 画面时自动使用平面地图。画面在状态、视角或指针变化时更新，移动动画尊重系统的减少动态效果设置。

- 点击地图选择位置，打开“共享标记”或圆盘内坐标提示查看详情；点击“前往这里”发送坐标目标并打开机器人通信。
- 在选中位置写下标记；勾选“共享给 R-07”才会进入机器人知识。
- 查看附近操作，检查、开门、拾取、清理和维修。物品可从相邻格取得。
- 背包有两个槽位；电池需要安装，氧气需要返回人类附近使用。
- WASD / 方向键直接控制机器人；手动操作会暂停当前任务。
- 修复供氧管能将每 TU 氧气消耗从 2 降至 1；辅助电路开关在设备间 (6,1)，机器人识别并靠近至同格或相邻格后，“附近操作”显示“开启电路 / 关闭电路”按钮，可以直接点击，也可以通过对话指挥 AI 操作。手动操作会暂停当前任务。通电能开柜和开门，也会激活电气危险。
- 已开启的门和柜在断电后保持开启。
- 与人类同格才可抱起；搬运移动消耗双倍电量。修复气闸后，把人类搬到 EXIT 并启动撤离。
- “停止行动”取消未提交动作；“继续任务”重新选择工具并重置本次运行预算。
- 需要额外授权的维修、放下物资或玩家、经过已知带电线路、机器人操作实体开关通电，会在工具执行前暂停，并在对应的机器人对话消息内显示影响、资源代价及“授权并继续 / 拒绝，重新决策”按钮。通信入口显示“待授权”徽标；打开后定位到请求，等待期间可关闭面板继续查看地图。提交时按钮禁用，处理或失效后移除。
- 授权只放行当前工具，沿用当前 ReAct 循环和剩余预算，不增加一次模型请求；拒绝阻止该工具及当前批次余下调用，模型在下一轮选择其他方案。真实模式不通过指令关键词自动授权维修、放下、危险穿越或通电，使用现有按钮决定；规则演示中明确支持的简单维修或通电指令可以直接执行。授权不能绕过资源、视线、距离与胜负规则，开柜也不会隐式通电。
- 保存和自动保存写入 `.saves/`；点击“恢复存档”可按保存时间和对局编号选择具体存档，再点击“恢复所选存档”。重新启动会恢复最近存档并暂停机器人。回放滑块按已执行动作重现资源和结局。

游戏时间由有效动作推进，阅读、输入、等待模型和等待玩家均不扣氧气或电量。

对话框会记录每次工具调用的原始名称、模型传入的 JSON 参数及执行状态，包括部分执行、未执行和取消；记录随对话保存。模型提示词要求使用简体中文交流，思考模式保持关闭。

每局对局使用独立的本地存档目录，文件均为 UTF-8，可直接用文本编辑器打开：

```text
.saves/<对局 ID>/
  game.json                完整游戏存档，缩进排版
  game.md                  当前进度、最近对话和完整行动账本
  events.md                按时间追加的全部对话、行动、授权和工具日志
  models/
    000001-<时间>-<唯一 ID>.md
    000001-<时间>-<唯一 ID>.context.json
    ...
```

每次模型调用单独保存 Markdown 日志：包括调用时间、模型与设置、系统提示词、当次实际传入 pi 模型适配器的完整消息历史和工具定义、模型回复、工具参数与结果、资源状态、结束原因和 token 用量。配套的 `.context.json` 保留缩进后的完整请求上下文，便于核对；日志不会随界面最近 100 条消息的限制被截断。规则演示的每轮决策也会记录，失败、超时和取消的请求同样保留，模型请求开始前先写入上下文。

恢复对局后继续在原目录追加日志，不覆盖历史模型调用；原先 `.saves/<对局 ID>.json` 的存档仍可读取，恢复时生成新目录并保留旧文件。旧存档没有保存的历史模型上下文无法补回。日志不记录 API Key 或鉴权请求头，上游错误内容使用固定分类提示替代。

演示模式识别有限的中文目标，例如：

```text
修补我的供氧管
去设备间找电池并回来
前往 (6,1)
开启辅助电路
关闭辅助电路
维修气闸控制器
回来
抱起我
撤离
```

开关电路、开门、清障、物品使用等操作可通过“附近操作”完成，需要机器人靠近已识别对象。演示模式找电池时会搜索开关，并在通电前等待授权。演示解析器使用独立的有限语法，只支持上述简单目标；否定、条件、复杂复合句及不支持的表达会提示拆成简单指令或切换真实模型，不会提取其中一个关键词继续行动。

真实模式直接接收玩家原始指令和发送时选中的位置，由模型理解目标、否定、顺序及条件，并直接调用现有工具。无需先提交任务理解或结构化计划，程序不再通过关键词建立目标、提取授权或在完成第一个目标后自动结束。指令语义和自然语言资源要求由模型遵守，动作合法性、资源结算、运行预算和敏感授权仍由程序校验。

真实模式的 `finish_task` 只结束本次自动委托，界面显示“已结束”；实际维修、拾取、撤离及游戏胜负以地图、工具结果和规则状态为准。继续任务保留原始指令，切换模式重新设置对应解释方式；旧真实模式存档恢复时清除关键词生成的目标与授权并暂停，不影响已提交动作。

模型工具 `set_circuit({ targetId, on })` 和手动 HTTP `/action` 的 `{ kind: 'circuit', targetId, on }` 均只接受已识别且可触及的开关。旧存档自动补入或迁移开关至 (6,1)，保留资源、物品与原电路状态，清除旧位置的开关观察。账本记录开关操作时的位置，兼容旧位置和新位置动作混合回放；旧远程切换动作仅在历史回放中兼容。

## pi Agent 串行执行

`GameSession` 使用 pi 的 `toolExecution: 'sequential'`：

1. 模型一次返回最多 6 个工具调用。
2. `beforeToolCall` 检查指令版本、共享信息变化、授权及批次有效性。缺少授权时挂起该钩子，等待按钮决定；同意后重新检查状态，再放行原调用。
3. 每个动作由领域引擎验证、结算和提交；`move_to` 逐格检查并可中断。
4. `afterToolCall` 比较该工具前后的知识，生成 `newDiscoveries`、`stateChanges`、`invalidatedFacts`、`knownRefs`。
5. 普通结果继续执行批次；相关物资、阻挡或危险使余下调用跳过，并向模型请求新决策。
6. 有重大选择时等待玩家；每次运行最多 8 个模型请求、12 TU，连续两轮无进展会暂停。

模型不会在同一个响应中读到中间工具结果；工具间的校验与中断由应用代码完成。重要发现仍需新的模型推理。机器人没有雷达、隐藏物资 ID 或权威世界状态；模型文本不改变地图、资源或胜负。

## 接入真实模型

点击页面右上角 **“模型设置”**，选择“真实模型”、服务商和模型 ID 后直接应用。游戏默认复用本机 pi 用户目录 `~/.pi/agent/auth.json` 中对应服务商的 API Key 或 OAuth 登录凭据，无需再次填写。`PI_CODING_AGENT_DIR` 指定的自定义用户目录也会生效。再发送指令或点击“继续任务”，机器人就会通过 pi 请求真实模型。服务商和聊天模型列表直接来自 `pi-ai` 的内置目录，包括 DeepSeek、Anthropic、OpenAI、Google、OpenRouter 等；保留提供 Chat Completions 流式工具调用的自定义兼容接口。仅有动态目录、尚无本地模型列表的服务商不显示。

现有弹窗的 **“应用并设为新局默认”** 同时更新当前对局和新局默认，点击“新的一局”即可自动使用，无需再次配置。运行模式、服务商、模型、地址、超时和输出上限保存在 `.saves/model-settings.json`，重启后仍然生效；保存的默认设置优先于启动环境变量。弹窗显示新局默认，并可点击“使用新局默认”填入表单后应用。其他已有对局保留原配置，恢复存档沿用该局的模型。

模型 ID、API 类型、接口地址和兼容参数来自本地 pi 目录，服务商决定实际请求协议；不再由游戏逐个映射服务商。当前目录的 DeepSeek 默认模型为 `deepseek-flash`；其他模型可在设置中选择。Azure、Bedrock、Vertex 等还需按 pi 对应服务商的要求配置部署、区域或环境凭据。自定义接口需填写完整基础地址（例如 `https://example.com/v1`）和模型 ID；需要支持 `tools`、`tool_calls` 与 SSE 流式响应。接口地址不允许包含用户名、密码或查询参数。真实模式不会自动降级到规则演示。

DeepSeek 目录入口直接使用 pi 的完整模型定义，包括 `reasoning`、`thinkingLevelMap` 与 `compat`。自定义接口指向 `api.deepseek.com` 且模型 ID 在目录中时，同样继承这些参数，保证工具历史携带 `reasoning_content`。游戏当前使用 `thinkingLevel: off`，由 pi 转为 DeepSeek 的 `thinking: { type: 'disabled' }`。

服务进程需要外网权限。若由编码助手在网络受限的沙箱中启动，浏览器仍能打开本地页面，但服务端模型请求可能返回连接失败或 `EACCES`。请在本机正常 PowerShell 中执行 `npm run dev`，或允许编码助手在沙箱外启动服务。

凭据优先级为：页面手动覆盖 → 本机 pi 凭据 → 服务商支持的环境或系统凭据。游戏通过 pi 的 `RuntimeCredentials` 和 `Models` 复用鉴权流程，支持凭据环境变量引用、已有密钥命令解析及服务商自己的 OAuth 处理。普通读取不创建或改写 `auth.json`；OAuth 临近过期时，pi 会在文件锁内刷新并将新令牌写回该文件，避免并发重复刷新或破坏 pi 原有登录。刷新失败保留原凭据，不静默回退到环境密钥。凭据不会复制到游戏目录。每次请求重新读取，因此更新 pi 密钥后下一次请求即可使用新值。

页面仅显示凭据来源，不返回密钥；密钥不会写入浏览器存储、默认设置文件、游戏存档或对话。恢复存档或重启后自动读取 pi 凭据。可选的页面覆盖密钥仅保留在服务端内存，按服务商和接口基础地址隔离，同一次服务运行中新局和恢复存档可自动复用；填写框留空沿用已记住的对应接口密钥。重启后手动密钥清除，需要重新填写；使用 pi 登录或环境凭据则无需重复输入。自定义接口仅在地址为 `https://api.deepseek.com`（可带 `/v1` 等路径）时自动复用 DeepSeek 凭据，其他接口使用手动密钥或 `GAME_MODEL_API_KEY`。

也可复制 [.env.example](.env.example) 为 `.env`，填写对应密钥，`npm run dev` 会自动加载。已有环境变量优先于 `.env`。以下示例默认启用 DeepSeek：

```powershell
$env:GAME_AGENT_MODE = 'live'
$env:GAME_MODEL_PROVIDER = 'deepseek'
# 模型 ID 可省略，使用当前 pi 目录默认值。
# 已在 pi 中配置 DeepSeek API Key 时，无需再设置密钥。
npm run dev
```

Anthropic 使用 `GAME_MODEL_PROVIDER=anthropic`、`GAME_MODEL_ID=claude-sonnet-4-6` 和 `ANTHROPIC_API_KEY`。自定义接口使用 `GAME_MODEL_PROVIDER=compatible`、`GAME_MODEL_ID`、`GAME_MODEL_BASE_URL` 和 `GAME_MODEL_API_KEY`。目录服务的模型 ID 必须存在于当前 pi 模型目录。

设置支持 1–120 秒超时和 256–8192 tokens 输出上限，默认 30 秒 / 2000 tokens；模型请求禁用自动重试，OAuth 刷新沿用 pi 的策略。设置页通过 pi 的鉴权检查显示可用凭据，不刷新令牌或验证远程连接。切换模型会取消正在等待的请求、暂停委托并保留已提交动作。鉴权、限流、连接失败或超时会明确显示错误，可修正设置后继续；未执行动作不扣资源。模型回复中的通信文本也会显示，包含同时调用工具的回复。

真实模型会产生提供商 API 费用。已通过本地模拟 HTTP/SSE 接口运行真实 pi 提供方代码，验证请求、工具循环、取消、超时及密钥隔离；没有发起付费外部请求，提供商线上表现仍需配置密钥后实测。自然语言报告作为通信文本展示；确认事实以程序生成的发现、地图和行动账本为准。

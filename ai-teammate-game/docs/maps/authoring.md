# 新地图制作

使用现有实体类型和救援规则时，每张地图只需要一个 `content/levels/*.json` 文件。地图清单在服务器启动时自动扫描，不需要修改加载入口、注册表、坐标常量、提示词或模型代码。

## 制作流程

地图清单、当前预算和通关结果见[地图索引](README.md)；具体操作顺序见[通关说明](walkthroughs.md)。

1. 复制已通过救援验证的 [地图模板](template.json)，例如：

   ```powershell
   Copy-Item docs/maps/template.json content/levels/station-03.json
   ```

2. 在新文件内修改地图 ID、名称、尺寸、布局、起点、出口、房间、实体和资源规则。地图 ID 必须唯一；已有地图更新时递增 `version`。
3. 按新布局更新同一文件内的 `verification.actions`。备用路线放入 `verification.alternatives`，制作初期可暂时移除 `verification`；交付可通关地图时应补齐。
4. 运行 `npm run verify:levels` 检查目录内所有地图；重启 `npm run dev`，点击“新的一局”即可选择新地图。没有存档时，首次打开页面直接显示地图选择；有存档时恢复最近进度。

模板是用于起步的 7×5 小地图，不会自动加入正式地图列表。改布局后，模板原有的验证路线也需要同步更新。

## 同一个 JSON 内的配置

| 字段 | 用途 |
| --- | --- |
| `id`、`version`、`name` | 唯一标识、正整数版本、显示名称 |
| `width`、`height`、`tiles` | 宽高可以不同，均至少为 3；行数等于 height，每行长度等于 width |
| `humanStart`、`robotStart`、`exit` | 起点与出口，坐标从 0 开始，必须位于非墙格 |
| `rooms` | 任意名称及矩形范围；范围含端点，必须在地图内；可以为空数组 |
| `entities` | 实体类型、唯一 ID、名称、坐标、反射强度、补给种类、容器关系与供电要求 |
| `rules` | 完整的资源、感知、预算与动作消耗配置；可先沿用模板后调整 |
| `verification`（制作期可选） | 本地图完整通关路线，同时供游戏内规则通关和开发验证使用 |

`#` 是墙，`.` 是地面，`E` 是出口标记；实际出口位置使用 `exit`。`D`、`X` 是历史门位和障碍标记，实际门与障碍仍需在 `entities` 中定义。柜体、开关、气闸控制器会占据格子，交互时需要保留可达相邻格。使用当前胜利条件时，需要气闸控制器、可到达的撤离出口及符合维修消耗配置的材料。

服务接口、模型工具、三维和平面地图、坐标标尺、点击检测均读取本局的宽高。公共墙面材质自动组合，同类物体共享现有模型；添加地图不会要求复制美术代码。

本地规则演示支持“前往房间名”和“去房间名找电池并回来”等简单指令，房间名来自该地图。完整救援使用“规则通关”，读取本地图配置的主路线；新增地图无需添加专用脚本。

## 按地图配置自动运行预算

在每张地图自己的 `rules` 中设置，无需修改提示词或服务器代码：

| 字段 | 限制范围 |
| --- | --- |
| `actionTULimit` | 每次自动运行累计可消耗的 TU |
| `requestLimit` | 每次自动运行最多模型请求次数 |
| `toolLimit` | 单次模型响应最多放行的工具调用数 |

TU 预算按 `actionCosts` 逐个完整动作检查；同一次运行内，多轮模型请求共享 TU 和请求预算，工具数量限制则每轮重新计算。普通任务点击“继续任务”或发送新指令会重置运行预算；授权后继续使用原有剩余预算。完整规则通关按相同预算分段，到达预算后自动开启下一段；停止操作、路线偏离、资源耗尽或无进展会终止自动续行，单个动作超过整段 TU 预算时也会暂停。

AI 会收到本局配置、剩余 TU 和当前请求之后还能发起的模型请求数。`moveLimit` 是保留的历史字段，不再限制单次移动格数；移动按 TU 预算逐格检查。

修改后重启服务并新建对局生效；已有存档继续使用创建该局时保存的预算。预算增加不会补充氧气或电量，这些资源仍由各自的规则控制。`verification.actions` 验证完整救援及资源消耗，不受单次自动运行预算限制。

## 救援路线验证

`verification.actions` 是默认主路线（ID 为 `main`），使用游戏动作格式，模板包含一条完整示例。`move` 是走到相邻格的一步，不是模型工具 `move_to` 的自动寻路目标；实体 ID 必须对应新地图。验证器逐步执行真实规则，检查观察、距离、阻挡、资源消耗和最终撤离；危险穿越视为作者已经授权。它不请求模型，也不读写真实对局存档。

`verification.alternatives` 可按名称存放其他完整路线，例如 `"lower": [动作, ...]`。每条备用路线都从初始状态开始，必须自行完成救援；名称不能为 `main`。正式地图目前均配置主路线和 `lower` 清障路线。游戏内按钮执行主路线，统一验证命令执行全部路线。

本地规则通关将预设动作转换为现有 pi Agent 工具，仍经过知识、距离、资源、预算和胜负校验。“规则通关”明确委托整条演示路线，预设的维修、通电及危险穿越不再逐次弹出授权；普通简单指令和真实模型仍保持原有授权流程。路线不会进入玩家视图、真实模型上下文或回放帧。

启动时，已执行账本必须是主路线的前缀。停止或存档恢复后可以继续，不会重复已完成动作；手动操作偏离路线后会提示新建对局，不会瞬移、补资源或重置世界。删除路线、配置非法步骤或预算不足都不会被当作成功通关。

可以游玩后从 `.saves/<对局 ID>/game.json` 中取出 `engine.ledger` 各条记录的 `action`，作为验证路线。该文件保留完整账本，前端玩家视图仅保留最近部分记录。

```powershell
npm run verify:levels
npm run verify:routes
```

`verify:levels` 自动发现所有地图并执行全部已配置路线。未配置 `verification` 的地图只报告格式通过，并明确标注未验证救援可行性；配置了路线但执行失败或没有成功撤离时，命令失败并指出地图、路线及步骤。

`verify:routes` 要求每张正式地图都有路线，通过后统一更新本目录的 [route-ledgers.json](route-ledgers.json)，包含地图版本、规则及逐动作资源账本。新增地图、修改布局或调资源后重新运行即可，不再维护专用坐标脚本。`scripts/routes.ts` 仅保留旧测试入口，实际也读取地图 JSON。

## 存档与地图更新

新存档包含创建该局时的完整地图副本，恢复与回放使用该副本。修改尺寸、资源、实体或移除地图文件后，已有对局仍按原地图运行；新局使用服务器启动时读到的新配置。

旧存档没有地图副本时，按其 `levelId` 和 `levelVersion` 匹配已安装地图。缺少匹配版本会明确拒绝恢复，不会套用另一张地图。需要保留这类旧存档时，应先在对应版本仍可用时恢复并保存，使其补入地图副本。
